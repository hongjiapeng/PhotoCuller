### 怎样判断这条路线是否适合

对同一对照片依次比较旧椭圆、未经修边的 BiSeNet、修边后的 BiSeNet；在结果下拉框切换底图、对齐来源和最终 Mask，并用 100% 检查。绿色只是单张图候选蒙版；最终取两图交集，补回有时需要两张图一起补。

| 检查 | 可继续验证的表现 | 不适合当前来源/路线的表现 |
| --- | --- | --- |
| 衣领与背景 | 预先标注的衣领区域相对底图差为 0；没有明显借入后排衣服 | 假头发/帽子仍连着衣服，修边后仍露出重影 |
| 脸与姿态 | 眼睛、嘴、耳朵来自同一完整来源头，100% 下轮廓连续 | 需要扭曲五官或大幅挪动才能放正，脖子方向明显冲突 |
| 修整成本 | 少量局部笔划即可稳定收尾；记录每头耗时、笔划数和撤销次数 | 多次重框或逐像素描发丝，手工成本接近完整抠图 |
| 导出一致性 | PNG 原始尺寸，像素与同参数调试结果一致；原片 Hash 不变 | 仅缩略图自然、高清有边缘/蒙版错位 |

建议将“每头修整不超过 30 秒”作为下一轮试用目标，**这是待测目标，不是已测结论**。本组约百像素宽的人脸和单一场景不足以判定产品可用，仍需多发型、24MP+ 原生照片、遮挡与帽子样本。自动路线默认不含帽子，有帽照片需要明确补回或另行设计分割配置。

模型准备：运行 `Get-BiSeNetModels.ps1`。默认缓存 `%USERPROFILE%\.cache\GroupTake.Poc\models\bisenet\`，也可用“选择分割模型”加载经 SHA256 验证的原版 ResNet18/34。改用用户目录缓存是因为开发工具创建的 LocalAppData 文件在外部应用/原生选择器下不可见；旧缓存没有删除。应用不调用 Python，不上传照片。Runner 同样支持 `--case private.json --segment model.onnx --output new-directory`，用于复现 UI 算法。

## 实现细节

### 当前整头路线

`HeadReplacementService` 按两个人头框的高度计算统一缩放，以框中心计算平移；可手调整体旋转、缩放系数、横纵偏移。没有非等比拉伸、五官变形或生成式补画。框比例差异过大、越界、无效参数或来源覆盖不足会明确报错。

Mask 是底图头框内的椭圆。Alpha 用到 Mask 内边缘的距离场和 smoothstep，羽化仅向内发生。结果从底图克隆，只有支持域内的像素被写入。支持域外 BGR 像素必须完全相同。整头模式没有关键点，因此调试指标的重投影误差为 `null`，不能把它当作零误差。

默认羽化半径 8 **原图像素**。不同照片中的头部像素大小不同，需人工调整；半径过大时原头会透出，过小时边缘明显。框选和微调本身也会影响效果。

### 保留的失败路线

五个点按**画面左眼、画面右眼、鼻尖、画面左嘴角、画面右嘴角**排序。`EstimateAffinePartial2D` + RANSAC 得到相似仿射矩阵，检查所有点（包括被 RANSAC 排除的点）的误差，拒绝明显离群和大旋转。保存完整 2×3 矩阵。

局部内脸椭圆覆盖眼、鼻、嘴和少量脸颊。NormalClone/MixedClone 调用 `Cv2.SeamlessClone`，随后仅把 Mask 内的结果写回底图，强制恢复 Poisson 矩形求解域中可能改变的其他像素。

失败原因：嘴巴变化是非刚性运动，用嘴角一起拟合会牵动眼鼻位置；有限五点和局部 Mask 不能处理脸部轮廓、下巴与姿态的整体变化。MixedClone 还可能混入底图旧的五官梯度，产生双重纹理。低重投影误差不等于自然的合成。

YuNet 2023 使用已有 OpenCV DNN CPU API，不增加 ONNX Runtime 依赖。当前 OpenCvSharp 没有 `FaceDetectorYN` 包装，按 OpenCV 官方 stride-head 定义解码并做 NMS。两图分别显示所有检测框，用户明确选同一人；编号不代表身份。检测失败可手动选点。首版样本检测数量 27/27/28/28，未逐脸标注真值，不能报告准确率；海报中的脸也可能被检测。

### 输入、视口与导出

- JPEG/PNG 加载经 EXIF 自动定向，再转为 BGR8；原文件只读。不同尺寸允许直接处理。
- Image 与选择框使用同一个原图坐标映射，处理 Uniform 留白、缩放和拖动。框可以重新绘制、拖动、拖四角调整。
- 100% 按物理显示像素校正 DPI，绝对缩放不随窗口尺寸变化；默认结果不遮盖人脸标记。
- 解码、配准、融合和图像编码在后台执行；串行操作避免换图时释放正在处理的 Mat。关闭窗口会取消并等待安全释放。
- OpenCV 原生调用不能中途强制终止；取消在调用之间检查，Alpha 逐行检查。UI 会说明正在等待当前调用。
- 高清导出重新执行原分辨率合成，输出尺寸等于 EXIF 定向后的 A。导出到用户选择的文件夹，文件名支持 `.png/.jpg/.jpeg`，可设置 JPEG 质量。
- 不用 SavePicker 避免它提前创建/替换文件；同目录临时文件编码完成后以“不覆盖”移动发布。拒绝已存在路径和源文件路径，失败清理临时文件。
- 未实现 ICC 色彩管理、RAW、透明 PNG 合成和原元数据复制；这是 8-bit BGR/sRGB 假设下的验证。JPEG 重编码会在 Mask 外产生有损差异，像素保护验收应看内存结果或 PNG。

## 运行与复现

在仓库根目录 PowerShell：

```powershell
./experiments/GroupTake/BuildAndRun.ps1
dotnet test src/GroupTake.Poc.Tests/GroupTake.Poc.Tests.csproj --configuration Release
dotnet test src/PhotoCuller.Tests/PhotoCuller.Tests.csproj --configuration Release
```

完整构建沿用 VS MSBuild，不能用只跑普通 C# 编译的结果代替 WinUI XAML 验证：

```powershell
$msbuild = & "${env:ProgramFiles(x86)}/Microsoft Visual Studio/Installer/vswhere.exe" -latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1
& $msbuild PhotoCuller.slnx /restore /t:Rebuild /p:Configuration=Debug /p:Platform=x64 /m
```

算法复现：复制 `head-case.example.json` 到私人目录，填写本机路径和完整头框，再执行：

```powershell
dotnet run --project src/GroupTake.Poc.Runner -- --case C:/Private/head-case.json --output C:/Private/new-head-case
```

输出目录必须不存在。旧路线必须明确写 `"Mode": "Face"` 并提供五个点。可选旧检测模型由 `Get-YuNetModel.ps1` 下载并校验 SHA256；关闭 BiSeNet 的手动椭圆路线无需模型。

## 局限、下一步与迁移

1. 椭圆不是精确头发分割。蓬松头发、耳朵边缘、其他人遮挡、手指/眼镜反光、脖子方向和复杂背景仍可露馅；大幅侧脸不在第一阶段适用范围。
2. 两个框的位置/大小并不能自动判断同一人或姿态是否合适。错误框选可以生成错误结果；本路线没有自动姿态拒绝器，必须人工选择相近姿态。
3. 单一整头相似变换保持五官内部形状，但不能修复透视差异和颈部三维姿态。曝光/白平衡差异也没有被自动校正。
4. 当前一组约 10.7MP 样本不足以做产品判断。还需独立场景、原生 24MP+、闭眼/睁眼、不同发型、不同肤色和遮挡样本，并由用户在 100% 下验收。
5. 当前已实现语义蒙版与手动修边。下一步先收集修整耗时与用户视觉验收，再决定是否值得加入头发 Alpha matting、更多边界工具或局部色彩校正；不恢复嘴角驱动的全脸拟合。

迁移时可以直接搬出 Imaging、WinUI 和 Runner 三个目录，保留独立测试，把已有中央包版本固化到新仓库；它们不依赖 PhotoCuller 业务程序集。第一阶段结束前不建立正式 GroupTake 产品、不合并 main。当前判断是**保留可运行实验，继续验证整头替换；局部人脸自然融合仍未通过验收**。
